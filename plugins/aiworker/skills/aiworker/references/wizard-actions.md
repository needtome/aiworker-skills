# Actions of connected mode (MCP propose_changes)

The same closed list the panel's setup wizard uses. Every action has the fields `type`, `target`, `field`, `lang`,
`value`, `question`, `answer`, `index`, `payload` (unused ones empty). The server checks each one on proposal and again
on apply. 

- `persona_instruction_append` — Дополнить инструкцию личности
- `persona_instruction_replace` — Заменить инструкцию личности
- `persona_instruction_edit` — Точно заменить один фрагмент инструкции личности: target — id личности; find — точный фрагмент, который встречается ровно один раз; replace — новый текст фрагмента
- `plan_recommend` — Рекомендовать один активный тариф ИИ-сотрудника: plan — код тарифа из context.worker_interview.plans, reason — короткая причина по ответам владельца; payload JSON {"period":"month|year"}; тариф не оплачивается автоматически
- `persona_field` — Изменить имя, фамилию, пол или должность личности
- `persona_create` — Создать личность (консультанта)
- `persona_assignment_create` — Поставить профессиональную задачу личности: target — id своей доступной личности; payload — JSON {"title":"…","brief":"…","token_budget"?:1000–1000000}; для презентаций и генерации предложи оценочный бюджет до 600000 токенов; необязательный top-level original_request — точные слова клиента, только если известны; создание после «Применить», с повторной серверной проверкой роли, доступа и бюджета; token_budget ставь только если владелец сам назвал бюджет, иначе не указывай — сервер возьмёт оценку для такой работы
- `revision_restore` — Восстановить ревизию задания, коллекции или личности
- `persona_block_set` — Добавить или изменить обязательный блок ответов личности (persona_ask): field — имя блока, payload — JSON блока
- `persona_block_remove` — Убрать обязательный блок ответов личности: field — имя блока
- `server_add` — Предложить подключение сервера для аудита: payload JSON {"host","port","user","name","create_audit_user":true|false}; private key создаётся и хранится зашифрованным
- `server_test` — Предложить проверку SSH-подключения: target — id своего сервера из server list
- `server_audit_run` — Предложить запуск только чтения по активному перечню: target — id своего сервера
- `server_access_revoke` — Предложить владельцу отзыв доступа к своему серверу и удаление сохранённого private key; payload JSON {"remove_created_user":true|false}; после подтверждения вернуть одноразовую команду sudo для владельца
- `server_fix_propose` — Подготовить точный план исправления выбранных находок: target — id прогона, payload JSON {"finding_ids":[...],"safe_only":true|false}
- `server_fix_apply` — Предложить применение ранее показанного плана: target — id предложения. MCP не может подтверждать высокорисковые пункты; владелец отдельно отмечает каждый такой пункт на странице аудита сервера.
- `server_fix_rollback` — Предложить откатить подтверждённые исправления из резервных копий: target — id предложения
- `standing_assignment_create` — Предложить постоянное задание: target — persona_id; payload JSON {title,brief,task_type?,server_id?,settings?,mode:continuous|scheduled,min_interval_minutes?,frequency_unit:hours|days|weekly|months?,frequency_interval?,weekday:1..7?,local_time?,tokens_per_iteration,daily_token_budget,monthly_token_budget,daily_external_actions_limit?,auto_approve_actions?}. Для именованного аудита задайте task_type=persona_audit и settings {audit_id,sites?,lang?,pipeline_inputs?,probe_permission?}; повторное создание того же audit_id обновляет одну постоянную запись; сервер проверит роль, доступ и URL.
- `standing_assignment_update` — Предложить изменение постоянного задания: target — standing_assignment_id; payload — поля расписания/бюджетов/settings или {state:pause|resume|stop}. Для именованного аудита передайте settings {audit_id,sites,lang?,probe_permission?}; pause приостанавливает существующую запись. Все изменения применяются только после apply_changes.
- `ai_architecture_report` — Подготовить только отчёт об архитектуре ИИ: payload JSON с description, source_text, source_url, source_worker_id?, probe_permission? и code_source? (GitHub repo/ref/token_secret, публичный GitHub URL {type:"public_url",url} или ZIP {type:"uploaded_zip",file_id} из file_upload с repository_archive=true); токен передаётся только по имени заранее сохранённого секрета REPO_AUDIT_ либо подключённого сайта GitHub и никогда не кладётся в payload. Публичный URL читается через SSRF-защищённый GET, а apply_changes сразу ставит отчёт в очередь и возвращает ссылку со статусом.
- `ai_security_report` — Подготовить только отчёт о безопасности ИИ: payload JSON с description, source_text, source_url, source_worker_id?, probe_permission? и code_source? (GitHub repo/ref/token_secret, публичный GitHub URL {type:"public_url",url} или ZIP {type:"uploaded_zip",file_id} из file_upload с repository_archive=true); для исходного server-side кода можно указать auditor_role=server_security_auditor; токен передаётся только по имени заранее сохранённого секрета REPO_AUDIT_ либо подключённого сайта GitHub и никогда не кладётся в payload; исправления только после отдельного запроса владельца
- `specialist_review` — Проанализировать существующий материал выбранной платформенной личности: target — id специалиста; payload JSON с source_url и/или source_text и/или source_ref (knowledge_source:<id>, worker_knowledge_source:<id>, mailing_template:<id>, presentation:<id>, persona_instruction:<id>, chat_greeting:<id>), focus?, lang?=ru|en|uk, format?=html|sheet|doc. Источники и объекты принадлежат этому аккаунту; отчёт только для чтения.
- `specialist_checklist` — Создать чек-лист по просьбе владельца выбранным платформенным специалистом: target и platform_role_persona_id — id одной включённой личности; payload JSON {topic,goal,context?,source_url?,source_text?,source_ref?,lang?}. source_ref может указывать только на объект аккаунта, source_url читается с SSRF-защитой; результат — новая версия чек-листа.
- `persona_audit_run` — Запустить именованный аудит из каталога специалиста: target и platform_role_persona_id — id одной включённой платформенной личности; payload JSON {audit_id,sites?,pipeline_inputs?,lang?,probe_permission?}. Для ai_architecture_site probe_permission принимает none (по умолчанию) или safe_read_only; второе значение разрешает до двух безопасных нейтральных вопросов чату через штатный preview с обычным лимитом токенов. Исходные пути URL сохраняются, страницы читаются через SSRF-защищённый GET. SEO-конвейеры принимают page_url, target_query, competitor_urls, region, language и export_rows из клиентской выгрузки; числа считает сервер. После apply_changes возвращается ссылка на queued assignment.
- `ui_design_preview` — Подготовить локальный HTML/CSS-концепт веб-интерфейса: в поручении target=0, концепт принадлежит заданию и аккаунту и не привязывается к сотруднику/чату; вне поручения target — id ИИ-сотрудника. payload JSON {"brief": описание экрана, необязательные "brand_choice"/"brand_site_url"}. Фирменный стиль автоматически определяется по профилю аккаунта, сайтам чатов, базе знаний и URL в брифе; спроси владельца один раз только если источник не найден. Возвращает HTML, CSS, обоснование и ссылку локального предпросмотра без внешних ресурсов.
- `design_reference_add` — Добавить референс дизайна компании после подтверждения владельца: payload JSON {"role":"all_designers|ui_web_designer|ux_designer|graphic_designer|brand_identity_designer|mailing_designer|deck_designer","title"?,"note"?,"url"? или "staged_id" + "name"}; загрузка остаётся временной до apply_changes
- `worker_instruction_append` — Дополнить инструкцию ИИ-сотрудника
- `worker_instruction_replace` — Заменить инструкцию ИИ-сотрудника
- `attention_hide` — Скрыть строки с требующими внимания диалогами или вопросами: target — id ИИ-сотрудника, payload — JSON {"all":true} либо {"items":["c:<conversation_id>","q:<question_id>"]} из attention_items
- `wizard_save` — Сохранить шаг мастера первого запуска: target — id ИИ-сотрудника или 0, field — step1|step2|step3|step4|step5, payload — поля шага; step5 запускает сотрудника после подтверждения
- `worker_pause` — Поставить ИИ-сотрудника на паузу или возобновить: target — id сотрудника, value — pause|resume
- `worker_update` — Изменить настройки ИИ-сотрудника кроме инструкции: target — id сотрудника, payload — JSON полей из panel_settings; инструкцию меняй отдельным worker_instruction_append/replace
- `worker_features` — Изменить набор включённых функций ИИ-сотрудника: target — id сотрудника, payload — JSON {"on":["telegram","browser",…]} из panel_settings.features
- `worker_identity` — Сгенерировать и назначить новую личность ИИ-сотруднику: target — id сотрудника; старая личность остаётся в аккаунте
- `tenant_storage` — Изменить место хранения файлов аккаунта: payload — JSON {"mode":"off|files|core_data","node_id":ID|null,"region_label":"…"}; узел должен быть подключённым BYOS-узлом этой компании
- `invite` — Пригласить коллегу в аккаунт: payload — JSON {"name":"…","email":"…","role":"owner|manager|moderator"}; письмо отправится после apply_changes
- `notification_preferences` — Изменить настройки уведомлений: field user с payload {"prefs":{"tg_draft":true,…}} меняет общее событие для выбранных каналов (неуказанные переключатели сохраняются); assistant_usage и panel_* остаются личными. Field webhook меняет подписанный вебхук событий; URL вебхука никогда не возвращается
- `notification_test` — Отправить тестовое событие на уже настроенный webhook аккаунта; target не нужен, URL и ответное тело не возвращаются
- `brand_style_set` — Сохранить стиль бренда компании: payload — JSON с description, colors, fonts, logo_url, tone, signature, legal_footers, button_style и do_dont
- `brand_style_detect_from_site` — Определить стиль бренда по публичному сайту после подтверждения владельца, сохранить новой ревизией и показать найденные значения; target — id ИИ-сотрудника, payload — JSON {"url":"https://…","designer_role":"mailing_designer|deck_designer|ui_web_designer"}; генерация не запускается
- `mailing_template_create` — Создать черновик шаблона рассылки: target — id ИИ-сотрудника, payload — JSON {"name","brief","source_text","variants"}
- `mailing_template_generate` — Сгенерировать или переделать варианты шаблона: target — id ИИ-сотрудника, payload — JSON {"name","brief","source_text","instruction","template_id"?}
- `mailing_image_generate` — Создать платное изображение для шаблона рассылки: target — id шаблона, payload — JSON {"brief","aspect"?,"placement"?}; перед применением покажи стоимость
- `mailing_template_update` — Изменить черновик или готовый шаблон: target — id шаблона, payload — JSON {"name","brief","source_text","variants","selected_variants","status"}
- `mailing_template_archive` — Переместить шаблон рассылки в архив без удаления: target — id шаблона
- `mailing_template_restore` — Восстановить ревизию шаблона как новую ревизию: target — id шаблона, field — номер ревизии
- `mailing_revision_restore` — Восстановить ревизию стиля бренда или шаблона как новую ревизию: target — id объекта, field — номер ревизии, payload — JSON {"entity_type":"brand|template"}
- `deck_create` — Создать черновик презентации без отправки: target — id ИИ-сотрудника или 0, payload — JSON {"name","goal"?,"audience"?,"presentation_type":"speaker|reading|commercial_offer|investor_pitch"?,"presentation_template_id"?,"slides"?}; тип по умолчанию speaker
- `deck_generate` — Предложить генерацию или переделку презентации: сначала установи цель, аудиторию и тип (speaker по умолчанию; reading — без докладчика; commercial_offer — продающее предложение; investor_pitch — инвесторам, инкубаторам или акселераторам), цель, аудиторию и тип бери из слов владельца и не переспрашивай уже названное; до слайдов о продукте прочитай product_facts; используй подтверждённые тарифы, лимиты, возможности и каналы. Чего нет в источниках (traction, выручка, команда, сумма и условия инвестиций) не выдумывай: оставь явные места «[уточнить: …]» и перечисли владельцу. Не помещай инструкции, служебные заметки и мета-комментарии в текст слайдов. payload — JSON {"name"?,"brief"?,"goal"?,"audience"?,"presentation_type"?,"source_text"?,"knowledge_source_id"?,"presentation_template_id"?,"presentation_id"?,"instruction"?}; применить только после согласия владельца
- `deck_image_generate` — Создать платное изображение для слайда: target — id презентации, payload — JSON {"brief","aspect"?,"placement"?}; перед применением покажи стоимость
- `deck_update` — Изменить слайды, цель, аудиторию, тип или статус презентации: target — id презентации, payload — JSON {"name"?,"goal"?,"audience"?,"presentation_type":"speaker|reading|commercial_offer|investor_pitch"?,"status":"draft|ready","slides"?,"presentation_template_id"?}
- `deck_regenerate_slide` — Переделать один слайд по инструкции: target — id презентации, field — номер слайда начиная с 1, payload — JSON {"instruction":"…"}
- `deck_archive` — Переместить презентацию в архив без удаления: target — id презентации
- `deck_restore` — Восстановить ревизию презентации как новую: target — id презентации, field — номер ревизии
- `deck_export_pdf` — Предложить экспорт презентации в PDF: target — id презентации; файл появится после подтверждённого apply_changes
- `deck_export_pptx` — Предложить экспорт презентации в редактируемый PPTX: target — id презентации; файл появится после подтверждённого apply_changes
- `locale` — Изменить язык панели владельца: value — ru|en|uk
- `size` — Изменить размер интерфейса панели владельца: value — compact|default|large
- `channel_account_connect` — Подключить собственный номер сотрудника: target — id сотрудника, field — whatsapp|telegram|imo|max, value — номер телефона; после применения вернуть ссылку на панель и состояние входа, для Telegram — короткоживущую QR-ссылку; коды, пароли и строку сессии через MCP не возвращать
- `email_sender_connect` — Подключить SMTP-сервис отправки почты: сначала покажи варианты из context.email_sending_providers с описанием и ссылкой регистрации/ключа; target 0; payload JSON {provider,host?,port?,region?,from_email,from_name,domain?,daily_limit?,reply_channel_account_id?}; value — JSON {username,password} со ссылками вида [ключ#N ••••1234], а не секретами; для провайдеров с фиксированным логином username можно опустить. Секреты будут зашифрованы и скрыты в предложении.
- `email_sender_test` — Проверить SMTP-сервис почты без отправки письма: target — id своего сервиса; EHLO и AUTH выполняются после подтверждения действия.
- `email_sender_archive` — Отключить SMTP-сервис почты без удаления настроек и истории: target — id сервиса своего аккаунта.
- `platform_number_order` — Заказать номер AI Worker за $5/мес. за номер: target — id сотрудника, payload — JSON {"channels":["telegram","whatsapp"]}; один номер можно использовать в нескольких выбранных каналах; перед применением показать outreach_warning и получить number_order_acknowledgement
- `platform_number_cancel` — Отменить платный номер AI Worker и будущие начисления: target — id platform_number_addon из channel_accounts; постоянные бесплатные номера отменить нельзя
- `specialists_addon_enable` — Запросить подключение «Специалистов Max»; после предложения требуется apply_changes владельца, затем отдельная оплата по ссылке
- `specialists_addon_cancel` — Запланировать отключение «Специалистов Max» в конце оплаченного периода через propose_changes → apply_changes
- `specialists_addon_keep` — Отменить запланированное отключение «Специалистов Max» через propose_changes → apply_changes
- `faq_add` — Добавить вопрос в FAQ
- `faq_update` — Изменить вопрос FAQ
- `faq_delete` — Удалить вопрос FAQ
- `company_profile_set` — Предложить изменение карточки компании: payload — JSON с полями name, websites, description, products, conditions, contacts, tone, languages; пропущенные поля сохраняются как есть
- `company_source_add` — Предложить источник общей базы знаний аккаунта: field — site|url|text|faq, value — URL или текст; payload — JSON с professional_mode (по умолчанию false/Auto), chunking_strategy fixed|fixed_overlap|structure|semantic, chunking_profile и настройками сайта. Только professional_mode=true включает ручную стратегию; semantic требует semantic_confirmed=true, сводка показывает оценку токенов и списание с лимита компании. Для сайта сервер показывает предпросмотр и предел тарифа до применения
- `chat_languages` — Языки чата: payload — JSON {"languages":["ru","uk"],"default":"ru"}; от 1 до 10 кодов WebChat, основной язык должен входить в список
- `chat_retrieval_profile` — Профиль поиска по умолчанию для профессиональных источников чата: value — balanced|catalog|meaning
- `chat_greeting` — Приветствие чата
- `chat_suggestions` — Быстрые вопросы чата
- `chat_name` — Название чата
- `chat_display_name` — Имя консультанта в чате
- `chat_title` — Подпись под именем в чате
- `chat_tab_label` — Надпись на боковой вкладке чата
- `chat_appearance` — Вид чата
- `chat_leads` — Заявки из чата
- `chat_enabled` — Включить или выключить чат
- `chat_site_add` — Разрешить чату работать на сайте: добавить домен в «Сайты, на которых можно разместить чат» (value — домен или адрес сайта, *.example.com — со всеми поддоменами)
- `chat_site_remove` — Убрать сайт из списка «Сайты, на которых можно разместить чат» (value — домен)
- `chat_install_request` — Подготовить заявку на бесплатную установку онлайн-чата: target — id чата, field=free; доступы владелец вводит только в защищённой форме панели, пароли через мастер не передаются
- `source_add` — Добавить в базу знаний сайт, страницу, Google Таблицу или Google Документ (field: site|url|gsheet|gdoc); payload: professional_mode, chunking_strategy, chunking_profile, retrieval_profile balanced|catalog|meaning, embedding_model (bge-m3 по умолчанию или разрешённая администратором text-embedding-3-large). Профиль retrieval_profile и выбор модели применяются в профессиональном режиме. OpenAI использует ключ клиента, если настроен, иначе ключ платформы и токены чата. Semantic требует semantic_confirmed=true после показа оценки расхода; сайт требует предпросмотр страниц
- `source_update` — Изменить стратегию, профиль поиска или модель эмбеддингов источника: target — id чата, field — id источника из context.chats[].sources; payload — professional_mode, chunking_profile, retrieval_profile balanced|catalog|meaning, embedding_model. Каталог должен разбиваться на записи. Смена модели переиндексирует только этот источник; OpenAI использует ключ клиента или токены чата через ключ платформы.
- `chat_create` — Создать онлайн-чат
- `automation_create` — Создать задание на сайте или в Telegram; необязательный top-level original_request — точные слова клиента, только если известны
- `automation_update` — Изменить задание; при изменении goal можно передать top-level original_request с точными словами клиента
- `webhook_inputs_set` — Настроить входы шаблона из вебхука
- `automation_targets_add` — Добавить сайты или группы в задание
- `automation_targets_remove` — Убрать сайты или группы из задания
- `audience_collect` — Создать сбор в интернете: контакты, сообщества, площадки, YouTube-каналы или исследовательские идеи и кейсы; payload web-сбора может содержать exclude_tlds, exclude_domains и search_plan {languages,regions}; необязательный top-level original_request — точные слова клиента, только если известны
- `audience_start` — Запустить или продолжить сбор (аудитория из context.audiences); payload research: {"token_budget":N,"review_drafts":true} — продолжить исследование с учётом прежнего расхода или проверить сохранённые черновики
- `audience_pause` — Поставить сбор контактов на паузу
- `audience_finish` — Завершить сбор контактов сейчас (собранное остаётся)
- `audience_archive` — Убрать аудиторию в архив без удаления (контакты остаются)
- `audience_unarchive` — Вернуть аудиторию из архива на паузу без автоматического запуска сбора: target — id аудитории
- `audience_restart` — Начать поддерживаемый сбор полностью заново: новое поколение с нуля (прежний результат сохраняется; исследовательские коллекции заново запускаются созданием отдельной коллекции)
- `audience_restore` — Сделать текущим сохранённое поколение аудитории (field — номер поколения)
- `audience_description` — Описание сбора и критерии владельца: target — id аудитории, field — set (заменить) или append (дописать), value — текст до 20000 символов. Для уточнения можно передать top-level original_request с точными словами клиента. Планировщик запросов и оценка соответствия читают описание; само описание не запускает сбор и не меняет цель или строки
- `helper_attach` — Прикрепить платформенного помощника к своему сбору или заданию: field — audience|automation_task, target — id объекта, payload — JSON {"step":"search_plan|quality_review|texts","platform_role":"ключ роли","token_budget_month":50000,"token_budget_run":8000,"auto_apply":false}; роли берутся из helper_catalog в get_account. Доступны на Max или с дополнением «Специалисты Max»
- `helper_update` — Изменить помощника: target — id из audience_status.helpers/task_status.helpers, payload — JSON со status active|paused, token_budget_month, token_budget_run и auto_apply (только search_plan)
- `helper_detach` — Снять помощника с объекта, сохранив журнал: target — id из audience_status.helpers/task_status.helpers
- `helper_run` — Запустить помощника вручную без отправки и публикации: target — id помощника; для texts необязательный payload {"instruction":"…","data":{…}}; результаты остаются черновиком или предложением владельцу
- `source_retry` — Прочитать источник знаний чата заново (после ошибки или чтобы обновить): target — id чата, field — id источника из context.chats[].sources
- `source_delete` — Убрать источник знаний из базы чата (по просьбе владельца, например ошибочную ссылку или дубль): target — id чата, field — id источника из context.chats[].sources
- `source_url_set` — Исправить ссылку источника знаний чата (в ссылке ошибка, документ переехал) и сразу прочитать его заново: target — id чата, field — id источника из context.chats[].sources, value — правильная ссылка того же вида (Google Документ — на документ, Таблица — на таблицу)
- `site_check` — Проверить заново, на чём сделан сайт чата и как поставить на него чат: target — id чата, value — сайт из списка «Сайты, на которых можно разместить чат»
- `audience_configure` — Настроить сбор без запуска и без нового поколения (строки сохраняются): target — id аудитории; у любого веб-сбора — payload {"target_count":N,"exclude_tlds":["ru","su","by"],"exclude_domains":["forum.example.com"],"search_plan":{"languages":["uk","ru","en"],"regions":["Украина"]}}; search_plan languages/regions и доменные исключения поддерживаются у компаний, площадок, Telegram и сообществ. Только у сбора компаний доступны cities, synonyms, directory_sources, fields, filter_directories и overseer {goal,max_target}. Цель ограничена оставшимся месячным лимитом тарифа; token_budget и Maps budget менять нельзя
- `audience_row_upsert` — Добавить в существующую аудиторию (сбор компаний, сообществ или площадок) одну найденную вручную организацию или обновить её строку: target — id аудитории, payload — JSON строки (ключ — точный домен организации)
- `audience_share` — Предложить владельцу поделиться результатами одной своей аудитории: target — id аудитории, payload JSON {"email":"email владельца другого аккаунта","note":"необязательное сообщение"}; только propose_changes, затем apply_changes после явного согласия владельца; принятие выполняется только в панели
- `audience_rows_select` — Добавить строки аудитории в избранное или снять отметку: target — id аудитории, payload {"row_ids":[точные ID строк до 200],"selected":true|false,"note":"необязательная заметка","status":"необязательный статус владельца"}
- `audience_recheck` — Перепроверить существующие строки аудитории компаний на их собственных сайтах без нового поиска и генерации либо активность форумов: target — id аудитории, payload — JSON {"scope":"legacy|unverified|all|forum_activity","limit":1..200,"row_ids":[необязательные точные ID]}; forum_activity только для строк forum; сначала предложить через propose_changes, выполнять только после apply_changes
- `overseer_create` — Создать ответственного — личность с ролью «ответственный», которая сама проверяет результат сбора и меняет способ поиска (запросы, слова, языки), досбор запускает сама, начать заново только предлагает владельцу: target — id аудитории (роль из её цели) или 0, value — имя (пусто — подберётся), field — пол, payload — дополнение к роли
- `audience_overseer_set` — Назначить сбору ответственного: target — id аудитории, field — id личности-ответственного (пусто — созданный в этом же наборе), payload — лимиты JSON {"max_iterations","token_budget","deadline_days","no_progress_rounds","min_progress","max_target"} (всё необязательно)
- `audience_overseer_state` — Ответственный сбора: value — pause (пауза), resume (продолжить) или unlink (отвязать, сбор идёт без него); target — id аудитории
- `audience_overseer_undo` — Отменить изменение ответственного (вернуть настройки поиска): target — id аудитории, field — номер решения из журнала (audience_status.overseer.journal[].id)
- `audience_overseer_apply` — Применить предложение ответственного начать сбор заново (новое поколение): target — id аудитории, field — номер решения (overseer.pending_proposal)
- `feature_request` — Оставить заявку разработчикам на функционал, которого пока нет
- `automation_activate` — Включить задание после проверки сценария
- `automation_run` — Запустить задание сейчас
- `automation_pause` — Поставить задание на паузу
- `automation_archive` — Убрать задание в архив (не запускается и не считается в лимите тарифа; найденное и отчёты остаются)
- `automation_unarchive` — Вернуть задание из архива (на паузе, включить — automation_activate)
- `automation_secret_set` — Сохранить ключ API, который владелец прислал в чат, в «Ключи доступа» задания
- `automation_step_place` — Где выполнять шаг задания: в браузере клиента или на сервере
- `automation_step_patch` — Включить чтение полного текста карточки в одном шаге задания
- `automation_split` — Разделить задание на несколько со своими расписаниями: источники сценария по группам сайтов, история найденного переходит в новые задания
- `automation_share` — Поделиться заданием: публичная ссылка, по которой любой установит себе такую же копию (без ключей, получателей и истории)
- `automation_share_revoke` — Отозвать ссылку «Поделиться» задания (одну или все)
- `automation_install_shared` — Установить себе задание по ссылке «Поделиться» (копия встанет на проверку)
- `account_secret_set` — Сохранить ключ API, который владелец прислал в чат, в «Ключи и доступы» аккаунта (для всех заданий)
- `account_variable_set` — Создать или изменить переменную аккаунта для повторного использования в заданиях: field — имя A-Z/0-9/_, value — значение из слов владельца, payload — JSON {label,sensitive}
- `account_variable_delete` — Удалить переменную аккаунта после подтверждения владельца: field — имя A-Z/0-9/_
- `ai_provider_route_set` — Обновить список моделей ИИ аккаунта: field задаёт назначение для совместимости, value — own|platform, payload — JSON списка собственных моделей. По умолчанию действует общий порядок моделей; явный маршрут назначения ставит выбранную модель первой, затем используется общий порядок как резерв. Ключи заранее сохранить через account_key_set.
- `step_run` — Выполнить разовый шаг на сайте, который действует (отправка, ставка, публикация): создаётся только инструментом MCP step_run, target — его номер; «Применить» запускает ровно предложенные значения
- `template_run_link` — Создать одноразовую ссылку запуска одобренной версии шаблона: target — id шаблона, payload — JSON с template/template_id, execution_target (where — совместимый псевдоним), worker_id/node_id или device_id, expires_in_hours, preset_inputs, locked_inputs, mode_limits и необязательным публичным HTTPS callback_url; ссылка возвращается только в результате «Применить», который является разрешением владельца на выбранные режимы
- `template_publish` — Опубликовать одобренную версию пользовательского шаблона для всех клиентов: target — version_id, field — slug, value — public; только после явного выбора владельца и повторной проверки при «Применить»
- `browser_mcp_allow` — Разрешить или запретить ИИ по MCP открывать страницы в браузере владельца (расширение AI Worker): target — device_id, value — on|off
- `chat_channel_connect` — Подключить к онлайн-чату собственный аккаунт Telegram, Messenger, Instagram Direct, WhatsApp Business или VK; value — JSON с учётными данными, которые скрываются в ключевом хранилище
- `chat_channel_disconnect` — Отключить канал онлайн-чата: field — telegram|messenger|instagram|whatsapp|vk
- `agent_route_create` — Создать маршрут ИИ-агента: события аккаунта сразу в Claude Code или Codex владельца
- `agent_route_update` — Изменить маршрут ИИ-агента
- `agent_route_pause` — Поставить маршрут ИИ-агента на паузу

The fields of each action, the payload JSON of automation_* / audience_collect and the rules come from the `guide`
tool of the connected account — read it before proposing.
